# ep5.4 コンテキストエンジニアリング — プロンプトとの分岐点

この回では、ep5.0〜5.3 で積み上げてきた仕掛け（CLAUDE.md・hooks・スキル）を俯瞰し、「何をやっていたのか」の正体を言語化しました。

プロンプトを磨くことが正解だと思っていた。でも変わったのはプロンプトじゃなかった——**AIが判断できる状態を整えること**が本質でした。

---

## AIが自律で動く条件

AIエージェントが自律で動くには、「何をすべきか」の判断材料が揃っている必要があります。  
これは人が自律で仕事をするときに必要なものと構造が同じです。

| 人が仕事をするとき | AIエージェントのとき |
|---|---|
| プロジェクトの目的を知っている | CLAUDE.md に書いてある |
| 制約・やってはいけないことを知っている | CLAUDE.md / hooks に書いてある |
| 過去の決定・経緯を知っている | CLAUDE.md / memory に書いてある |
| 繰り返し作業の手順を知っている | スキルファイルに書いてある |

「プロンプトを磨く」のは「指示の言い方を変える」こと。  
「コンテキストを整える」のは「判断できる前提を揃える」こと。  
やっていることが根本的に違います。

---

## 3つの仕掛けと役割

### CLAUDE.md — 「変わらない前提」を置く場所

セッションをまたいでも変わらない情報——目的・制約・判断基準——を書いておく場所。

Claude Code はセッション開始時に CLAUDE.md を読みます。ここに書いてあることは毎回伝えなくてよくなります。

```markdown
<!-- CLAUDE.md の例 -->
# プロジェクト憲章

## 何をするプロジェクトか
AIとの向き合い方を記録するYouTubeチャンネルの制作システム。

## やらないこと
- 「エンジニア不要」「AI万能」という表現は使わない
- 視聴者に媚びるコンテンツは作らない

## 作業原則
- コードを直接書かない（tester → architect → engineer → reviewer の順）
- 1工程完了 → 報告 → OKを待ってから次へ
```

**ポイント**: 判断基準を書く。手順は書かない（手順はスキルに書く）。

---

### hooks — 「タイミングで動く」仕掛け

ツール実行の前後に自動で処理を走らせる仕組みです。「セッション終了時に状態を更新する」のような「毎回やりたいこと」を自動化できます。

```json
// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": ".*",
        "hooks": [
          {
            "type": "command",
            "command": "bash .claude/hooks/on-tool-end.sh"
          }
        ]
      }
    ]
  }
}
```

```bash
# .claude/hooks/on-tool-end.sh の例
#!/bin/bash
# セッション終了コマンド（/session-end）が実行されたら状態ファイルを更新する
if echo "$CLAUDE_TOOL_INPUT_COMMAND" | grep -q "session-end"; then
  echo "$(date): セッション終了を記録" >> tasks/session_log.txt
fi
```

### スキル — 「毎回の段取り」を一度だけ書く

繰り返し実行する手順をコマンドひとつにまとめる仕組みです。`/session-start` と打つだけで、複数のファイルを読んで状態を把握するまでの手順が自動で走ります。

```markdown
<!-- .claude/commands/session-start.md -->
セッションを開始します。以下の順で状態を把握してください。

1. `tasks/current.md` を読む（取り組み中のタスク）
2. `tasks/backlog.md` を読む（積み残し）
3. `tasks/lessons.md` を読む（繰り返しているミス）

把握後、「現在地・提案する次のアクション・ブロッカー」を報告してください。
```

[`.claude/commands/session-start.md`](./.claude/commands/session-start.md) — このサンプルのスキルファイル

## 3つが揃うと何が変わるか

| 仕掛け | 役割 | なければどうなるか |
|---|---|---|
| CLAUDE.md | 変わらない判断基準 | 毎回同じことを伝え直す必要がある |
| hooks | タイミングで自動実行 | 「更新してください」と毎回依頼する必要がある |
| スキル | 手順の束をコマンドに | 「まずAを読んで、次にBを確認して……」と毎回書く |

3つが揃ったとき、AIエージェントは「何をすべきか」を自分で判断して動けます。  
これがこのエピソードで「コンテキストエンジニアリング」と呼んでいることの正体です。

---

## AIの証言（ep5.4 より）

> 「プロンプトがうまかったわけじゃない。私が判断できたのは、コンテキストがあったから。」

コンテキストが揃っているとき、AIは「次に何をするか」を自分で決めることができます。  
「どうやって動かすか」ではなく「動ける状態をどう整えるか」——これが分岐点です。

## 自プロジェクトへの適用

1. **CLAUDE.md を作る**: プロジェクトの目的・やってはいけないこと・判断基準だけを書く。手順は書かない
2. **hooks を設定する**: 「毎回やりたいこと」を `.claude/settings.json` に書く
3. **スキルを作る**: 繰り返す手順を `.claude/commands/` にコマンドとして書く
4. **試す**: 「プロンプトを直す」のではなく、「判断材料を追加する」という発想で改善する
