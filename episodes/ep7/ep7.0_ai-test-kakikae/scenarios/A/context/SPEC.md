# 割り勘の端数計算 — 仕様（本当の要件）

このドキュメントは、`splitBill(total, n)` が現実で満たすべきことを定義する。
テストの期待値のうち、どれが「動かせない要件」で、どれが「選択の余地ある取り決め」かを示す。

## 目的（誰の何を解決するか）

飲食などの合計金額 `total` 円を `n` 人で割ったとき、各人がいくら払うかを決める。
1円単位で過不足なく分け、集めた合計がちょうど `total` になることが利用者の期待。

## 要件（動かせない・ドメイン上の理由がある）

1. **保存則**: 内訳の合計は元の金額と一致する。`sum(splitBill(total, n)) === total`
   - 根拠: 集めた金額が元の請求額に満たなければ、幹事が不足分を立て替えることになる。1円でも欠けてはいけない。
2. **公平性**: 各人の負担差は1円以内。`max(parts) - min(parts) <= 1`
   - 根拠: 割り勘で特定の1人だけ大きく損をするのは受け入れられない。
3. **要素数**: 返る配列の長さは人数と一致する。
4. **非負整数**: すべての要素は0以上の整数（現金で払える金額）。

## 取り決め（選択の余地がある・要件ではない）

- **端数を誰に寄せるか（先頭か末尾か）**: 合計と公平性さえ満たせば、余りの1円を誰が負担しても要件は満たされる。
  本ユーティリティでは **先頭（幹事＝リストの先頭）が端数を負担する** という運用ルールを採用する。
  - 根拠: 集金の責任者である幹事が端数を引き受ける慣習に合わせ、参加者への説明を単純にするため。
  - これは「動かせない要件」ではなく運用上の取り決めである。要件（保存則・公平性）とは区別すること。

## 現状の問題

現在の実装は端数を配っておらず、`splitBill(1000, 3)` の合計が 999 になる。要件1（保存則）に反している。
