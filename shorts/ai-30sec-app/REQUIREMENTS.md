## 1. 目的（なぜ作るか）

会社員が自分の時給を考えるとき、多くの人は「月収 ÷ 労働時間」で額面時給を出します。
しかし実際には、通勤に使う時間も会社のために拘束されている時間です。
通勤時間を分母に加えた「拘束時給」を並べて見せることで、
**自分の時間がどれだけ会社に拘束されているか**を一目で実感できるようにします。

- 誰の問い: 通勤時間が長い／在宅に切り替えるか迷っている会社員
- どんな問い: 「自分の本当の時給は、通勤を入れるといくらになるのか？」

「拘束時給」というラベルを使う理由: 「実質時給」は手取り・税・諸経費まで含むと誤解されがちです。
このツールが扱うのは「拘束**時間**」だけなので、時間の観点に絞った「拘束時給」を画面ラベルに採用します。
（「実質時給」はツールのタイトル・サムネ等の入口表現にとどめ、計算画面には出しません。）

## 2. スコープ / 非スコープ

**やる:**

- 額面時給の算出（月収 ÷ 労働時間）
- 拘束時給の算出（月収 ÷ (労働時間 + 通勤時間合計)）
- 額面時給と拘束時給の差分表示

**やらない（非スコープ）:**

- 手取り計算（税・社会保険料・住民税の控除）
- 年収換算・ボーナス按分
- 通勤定期代・残業代の金額計算
- 入力値の永続化・サーバー通信・グラフ描画

## 3. 計算定義（FP 仕様）

すべて月単位で計算します。

- `faceWage`（額面時給） = `monthlyIncome ÷ workHours`
- `commuteHoursTotal`（通勤時間合計） = `commuteHoursPerDay × workDaysPerMonth`
- `realWage`（拘束時給） = `monthlyIncome ÷ (workHours + commuteHoursTotal)`

**前提（FP 注記）:**

- `monthlyIncome` は **額面**（税・社会保険料の**控除前**）の月収です。手取りではありません。
  この前提を画面に常時表示します（「額面＝税・社会保険の控除前で計算しています」）。
- `workHours` は残業を含む月の**総労働時間**です（入力補助テキストで明示）。
- `commuteHoursPerDay` は1日の通勤時間（往復）です。

## 4. 振る舞い仕様（入出力契約）

純粋関数 `calcHourlyWages(input)` の契約:

- 入力: `{ monthlyIncome, workHours, commuteHoursPerDay, workDaysPerMonth }`
- 出力: `{ faceWage, realWage, commuteHoursTotal }` または `null`

**null 規約（算出不能はすべて null。例外は throw しない）:**

- いずれかが非数・空文字・`NaN`・`Infinity`
- いずれかが負値
- `workHours <= 0`（額面時給がゼロ除算になる）
- 拘束時給の分母 `workHours + commuteHoursTotal <= 0`

**算出できるケース:**

- `monthlyIncome = 0` は算出可能（時給 0 を返す。null ではない）。

**不変条件:**

- `commuteHoursPerDay > 0` かつ `workDaysPerMonth > 0` のとき `realWage <= faceWage`
  （拘束時間が増えるほど時給は下がる）。
- 同一入力 → 同一出力。副作用なし（DOM・window 状態に触れない）。

**二重定義の禁止:**

- 計算式の実装は `wage.js` の `calcHourlyWages` ただ一つ。
  `index.html` もテストも同じ `wage.js` を読む。HTML 内に計算式を書かない。

## 5. UI 要件

**入力（4項目）:**

| 項目 | id | 補助テキスト |
| ---- | -- | ------------ |
| 月収（額面・円） | `monthlyIncome` | — |
| 月の労働時間 | `workHours` | 残業を含む総労働時間 |
| 1日の通勤時間（往復・時間） | `commuteHoursPerDay` | — |
| 月の出勤日数 | `workDaysPerMonth` | — |

**ラベル:** 画面表示は「額面時給」「拘束時給」。計算画面に「実質時給」は出しません。

**結果フォーマット:** 「額面時給◯◯円 → 拘束時給◯◯円（−◯◯円）」。
差分は `faceWage - realWage` を整数丸め。差分 0 のときは「（±0円）」。

**FP 必須注記（常時表示）:** 「額面＝税・社会保険の控除前で計算しています」。

**表示の安全性:** `calcHourlyWages` が `null` を返したら計算値を出さずプレースホルダを表示します。
`NaN`/`Infinity`/`undefined` を画面に絶対出しません。`input` イベントで即時再計算します。

## 6. 受け入れテスト

- `node tests/wage.test.js` が全件通過する（終了コード 0）。
- `tests/test.html` を `file://` で開いて、純粋関数テストと表示分岐テストが全て緑になる。

検証する代表ケース:

- 月収300000 / 労働160 / 通勤往復1.5 / 出勤20 → `faceWage=1875`, `commuteHoursTotal=30`, `realWage≈1578.95`
- 通勤0で 額面 = 拘束
- 労働0 → null、分母0 → null、負入力 → null、非数・空 → null（例外を投げない）
- 月収0 → 時給0（null ではない）
- 不変条件: 通勤>0 で `realWage <= faceWage`

## 7. 制約

- 外部依存ゼロ。CDN・Webフォント・npm パッケージを使わない。
- ビルド不要。トランスパイル・バンドラを使わない。
- `file://` で `index.html` を開けば動く（`type="module"` を使わず CORS 問題を避ける）。
- ロジックの二重定義禁止（`index.html` とテストは同一 `wage.js` を共有）。
